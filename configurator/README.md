# Mesh Network Configurator

Интерактивный конфигуратор для управления mesh-сетью с тремя вариантами интерфейса.

## Возможности

- ✅ Создание произвольного количества узлов (2-10)
- ✅ Автоматическая генерация случайной топологии
- ✅ Визуализация связей между узлами
- ✅ Отправка сообщений между любыми узлами
- ✅ Консоль для каждого узла с информацией:
  - Внутренние часы
  - Маршрутная таблица
  - Соседи
  - E2E ключи
  - Статистика
- ✅ **НОВОЕ:** Логи каждого узла в отдельном tmux окне

## Использование

### 1. Генерация топологии

1. Выберите количество узлов (2-10)
2. Нажмите "Сгенерировать топологию"
3. Программа создаст случайную топологию одного из типов:
   - **Цепочка (Chain):** NODE1--NODE2--NODE3--...
   - **Звезда (Star):** центральный узел соединен со всеми
   - **Кольцо (Ring):** каждый узел соединен с двумя соседями
   - **Дерево (Tree):** иерархическая структура без циклов
   - **Разреженная (Sparse):** 1-2 соседа на узел
   - **Средняя (Medium):** 2-3 соседа на узел
   - **Плотная (Dense):** 3-4 соседа на узел
4. Отображается тип топологии, связи и статистика

**Пример топологии:**
```
Тип: Средняя плотность (Medium)

NODE1: NODE2, NODE3
NODE2: NODE1, NODE3, NODE4
NODE3: NODE1, NODE2
NODE4: NODE2

Статистика:
  Всего связей: 4
  Среднее соседей на узел: 2.0
```

### 2. Запуск сети

1. Нажмите "Запустить сеть"
2. Все узлы запустятся в фоновых потоках
3. NODE1 автоматически станет Time Master
4. Между всеми узлами установятся E2E ключи
5. Появятся кнопки для открытия консолей

### 3. Отправка сообщений

1. Выберите отправителя из списка
2. Выберите получателя из списка
3. Введите текст сообщения
4. Нажмите "Отправить"

**Что происходит:**
- Если маршрут не найден → отправляется RREQ
- Если маршрут найден → сообщение шифруется и отправляется
- Используется E2E шифрование (pairwise keys)
- Вычисляются E2E MIC и Link MIC
- Промежуточные узлы пересылают, но не могут прочитать

### 4. Консоль узла

1. Нажмите на кнопку с именем узла (NODE1, NODE2, ...)
2. Откроется окно консоли с информацией:
   - Порт UDP
   - Список соседей
   - Роль (Time Master или нет)
   - Внутренние часы
   - Маршрутная таблица (destination, next_hop, hop_count, seq_num, lifetime)
   - Количество E2E ключей
   - Статистика (seen packets, seen RREQ)
3. Нажмите "Обновить" для обновления информации

### 5. Остановка сети

1. Нажмите "Остановить сеть"
2. Все узлы остановятся
3. Можно сгенерировать новую топологию

## Архитектура

### Генерация топологии

Алгоритм создает связную сеть:
1. Строит минимальное остовное дерево (все узлы связаны)
2. Добавляет случайные дополнительные связи
3. Каждый узел имеет 1-3 соседа
4. Гарантируется связность всей сети

### Сетевая модель

- Каждый узел работает на своем UDP порту (7000+)
- Узлы общаются через UDP сокеты
- Эмулируется LoRa broadcast (отправка всем соседям)
- Используется Python симуляция из `simulation/node/node.py`

### Безопасность

- **E2E шифрование:** каждая пара узлов имеет уникальный ключ
- **E2E MIC:** проверка целостности end-to-end
- **Link MIC:** проверка целостности на каждом хопе
- **AODV маршрутизация:** автоматическое обнаружение путей
- **Time sync:** NODE1 синхронизирует время всех узлов

## Примеры использования

### Пример 1: Простая сеть из 3 узлов

```
Топология:
NODE1 -- NODE2 -- NODE3

Действия:
1. Генерируем топологию (3 узла)
2. Запускаем сеть
3. Отправляем сообщение NODE1 → NODE3
4. Открываем консоль NODE2 (relay)
5. Видим, что NODE2 пересылает, но не читает сообщение
```

### Пример 2: Сложная сеть из 5 узлов

```
Топология (случайная):
NODE1 -- NODE2 -- NODE4
  |        |        |
NODE3 -----+------ NODE5

Действия:
1. Генерируем топологию (5 узлов)
2. Запускаем сеть
3. Отправляем NODE1 → NODE5
4. Открываем консоли всех узлов
5. Наблюдаем RREQ/RREP и установку маршрута
6. Отправляем сообщение
7. Видим маршрут в таблицах
```

### Пример 3: Тестирование AODV

```
1. Запускаем сеть из 4 узлов
2. Открываем консоль NODE1
3. Видим пустую маршрутную таблицу
4. Отправляем сообщение NODE1 → NODE4
5. Видим сообщение "Маршрут не найден, инициирован RREQ"
6. Ждем 2 секунды
7. Открываем консоль NODE1 снова
8. Видим маршрут к NODE4 в таблице
9. Отправляем сообщение снова
10. Сообщение доставлено!
```

## Технические детали

### Порты

- Базовый порт: 7000
- NODE1: 7000
- NODE2: 7001
- NODE3: 7002
- и т.д.

### E2E ключи

Для каждой пары узлов генерируется уникальный ключ:
```python
key = f"{node1}_TO_{node2}_KEY_2026".ljust(32, '!')[:32].encode()
```

Пример: `NODE1_TO_NODE3_KEY_2026!!!!!!`

### Маршрутизация

- Используется AODV протокол
- RREQ отправляется при отсутствии маршрута
- RREP возвращается от получателя
- Маршруты имеют lifetime (30000 тиков)
- Автоматическая очистка истекших маршрутов

## Отладка

### Проблема: "Маршрут не найден"

**Решение:**
1. Подождите 2-3 секунды после первой попытки
2. RREQ должен распространиться по сети
3. RREP должен вернуться
4. Попробуйте отправить снова

### Проблема: "Сообщение не доставлено"

**Решение:**
1. Откройте консоли всех узлов
2. Проверьте маршрутные таблицы
3. Убедитесь, что есть путь от отправителя к получателю
4. Проверьте, что все узлы запущены

### Проблема: "tkinter не найден"

**Решение:**
```bash
# Fedora
sudo dnf install python3-tkinter

# Ubuntu
sudo apt install python3-tk
```

## Ограничения

- Максимум 10 узлов (для удобства GUI)
- Топология генерируется случайно (нельзя задать вручную)
- Консоль показывает только текущее состояние (нет истории)
- Нет визуализации пакетов в реальном времени
